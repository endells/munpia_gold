# 문피아 구매·대여 — FlaskFarm 플러그인

**munpia_gold v0.1.2** — 로그인한 문피아 계정에서 무료·구매 완료·대여 기간이 남은 연재 회차를 TXT와 EPUB으로 저장합니다. `munpia_free v0.3.1`을 바탕으로 만든 별도 플러그인입니다.

**이미 이용 권한이 있는 회차만 조회합니다. 골드 결제·자동 구매·자동 대여·대여권 사용 기능은 없습니다.**

## 설치

FF **시스템 → 플러그인 관리**에 아래 주소를 입력하고 설치 후 FF를 재시작합니다.

```text
https://github.com/endells/munpia_gold
```

확인한 FF 설치기는 `.git`을 자동으로 붙이므로 주소 뒤에 `.git`이나 `/`를 붙이지 마세요. 대상은 Linux의 `flaskfarm/flaskfarm:4.0` 계열, Python 3.8 이상입니다. 이미지는 FF 공식 의존성에 포함된 Pillow를 사용합니다.

메뉴 이름은 **문피아 구매·대여**입니다. 무료판을 지우거나 교체할 필요가 없습니다. 이 플러그인은 무료판 설치 없이도 실행되며 설정, 로그인 쿠키, DB, 스케줄, 기본 다운로드 폴더가 별도입니다.

## 첫 실행

1. **설정**에서 컨테이너 내부 다운로드 경로를 지정합니다. **경로 선택** 버튼으로 폴더를 찾을 수 있습니다.
2. 문피아 쿠키를 입력하고 **로그인 확인 → 설정 저장**을 누릅니다. 무료판의 쿠키를 자동으로 가져오지는 않습니다.
3. **회차 선택**에 구매·대여한 작품 URL을 입력하고 **회차 분석**을 누릅니다.
4. 화면에 표시된 **구매완료** 또는 **대여 중** 회차 하나를 먼저 선택해 받습니다.
5. 결과를 확인한 뒤 전체 선택이나 자동 수집을 사용하세요.

작품 주소는 `https://m.munpia.com/novel/detail/작품번호`, PC 작품 URL 또는 숫자 작품 번호를 사용할 수 있습니다. 이 버전은 모바일 웹에서 본문을 열 수 있는 연재 회차를 대상으로 합니다. 앱 전용 EPUB 상품은 지원하지 않습니다.

## 접근 상태 판별

문피아 모바일 회차 화면과 회차 목록 API가 사용하는 필드를 기준으로 판단합니다.

| 서버 상태 | 화면 표시 | 새 본문 요청 |
|---|---|---|
| `purchased`가 실제 불리언 `true` | 구매완료 | 가능 |
| `remainRentSec`가 양의 유한 숫자이고 시간이 남음 | 대여 중 | 가능 |
| `free`가 실제 불리언 `true` | 무료 | 가능 |
| `rented=true`이지만 잔여 시간이 없거나 만료됨 | 대여 만료 | 제외 |
| 그 외 미구매·불명확한 상태 | 미구매 / 권한 미확인 | 제외 |

구매와 대여 기록이 동시에 있으면 구매 완료를 우선합니다. `rented=true`만 보고 접근을 허용하지 않습니다. 대여 잔여 시간은 회차 목록을 조회한 시점부터 경과 시간을 차감하고, 큐에서 꺼낼 때와 요청 간격 대기가 끝난 뒤 다시 확인합니다. 실제 열람 요청에서 서버가 접근을 거부하면 실패로 표시합니다.

수동으로 고른 회차도 실행 직전에 서버 목록을 다시 조회합니다. 화면의 체크 상태나 임의로 넘긴 회차 번호로 권한을 추가할 수 없습니다. 목록 확인을 거치지 않은 본문 요청, 결제·주문 API 주소는 클라이언트에서 차단합니다. 문피아 API 요청은 정해진 조회 주소의 GET만 사용합니다.

분석 화면의 구매·대여 상태는 분석 당시의 값입니다. 새로 구매하거나 대여한 뒤에는 다시 분석하세요. 한 번에 받을 최대 회차 수는 기본 10이며 필요하면 50 또는 100으로 올릴 수 있습니다. 무료 회차도 함께 포함해 전체 작품을 구성합니다.

## 쿠키 입력

1. Chrome에서 `https://m.munpia.com`에 로그인하고 작품 페이지를 엽니다.
2. Cookie-Editor 등 사용 중인 확장프로그램에서 **현재 사이트 쿠키 → JSON 내보내기/복사**를 선택합니다.
3. 여러 줄 JSON 전체를 FF의 **문피아 로그인 쿠키** 칸에 붙여넣습니다.
4. **로그인 확인 → 설정 저장** 순서로 적용합니다. 로그인 확인만으로는 새 쿠키가 저장되지 않습니다.

JSON 배열과 `{"cookies": [...]}` 형식을 지원합니다. 최대 256KB, 1000개이며 줄바꿈을 지울 필요가 없습니다. `domain`, `name`, `value`와 도메인 범위·경로·만료 정보를 읽어 모바일 문피아에 맞는 쿠키만 사용합니다. 기존 한 줄 Cookie 헤더(`이름=값; 이름=값`, 최대 16KB)도 지원합니다.

쿠키는 저장 후 입력란에서 지워지고 화면에 다시 보내지 않습니다. 빈칸으로 저장하면 기존 값을 유지하며 **저장 시 기존 쿠키 삭제**를 체크하고 저장하면 삭제합니다. 쿠키는 FF 데이터 경로의 `db/munpia_gold_cookie.txt`에 권한 0600으로 저장됩니다. 암호화 저장은 아니므로 데이터 백업에도 인증정보가 포함될 수 있습니다. 쿠키를 채팅이나 GitHub에 올리지 마세요.

쿠키 만료로 문피아가 로그인 필요 응답을 보내면 작업을 중단합니다. 새 쿠키를 등록하고 다시 실행하면 완료된 정상 파일은 건너뜁니다. 계정 상태·앱 제한·성인 인증 등의 서버 접근 제한은 변경하지 않습니다.

## 파일과 EPUB

기본 다운로드 폴더는 `{FF 데이터 경로}/downloads/munpia_gold`입니다. 시놀로지 NAS 폴더가 `/books`로 볼륨 연결되어 있다면 컨테이너 경로 `/books/...`를 선택하세요.

작품 폴더에는 다음 파일을 저장합니다.

- `00034_유령선 [회차ID].txt` — 첫 줄에 `34. 유령선`
- `작품명 [작품ID].epub` — 받은 회차의 합본
- `cover.jpg` — 실제 JPEG 표지
- `info.xml` — ComicInfo 형식의 작품·작가·소개·장르 등
- `metadata.json` — 작품 메타데이터
- `images/` — 본문 삽화·사진
- `.munpia_gold/entries/` — EPUB 재생성·삽화 재시도를 위한 원본 정보

EPUB은 표지를 첫 페이지에 넣고 본문 이미지도 원래 위치에 내장합니다. 기본 줄간격 1.8배, 문단 간격 0.55em, 왼쪽 정렬이며 설정에서 간격을 바꿀 수 있습니다. 리더 앱에서 글자 크기·글꼴·야간 모드를 사용할 수 있습니다. 이미지 실패 시 TXT는 유지하고 이미지 경고를 표시합니다.

**기존 파일 보완**은 이 플러그인의 이력에 등록된 회차를 대상으로 TXT 제목·표지·메타정보를 보완하고, 누락된 삽화를 다시 받고, EPUB 사용 시 합본을 재생성합니다. 회차를 다시 조회할 때도 현재 무료·구매·유효 대여 상태를 확인합니다. 무료판의 이력·파일은 자동으로 가져오지 않습니다. 이미 저장한 파일은 대여 만료 후에도 자동 삭제하지 않습니다.

## 예약 수집

설정 저장은 작품 목록과 설정만 반영하며 즉시 수집하지 않습니다.

- **저장된 목록 지금 받기**: 즉시 다운로드
- **자동 수집 사용**: 설정한 간격에 따라 다운로드
- 작품 목록·경로·쿠키만 수정: 기존 다음 예약 시각 유지
- 자동 수집 활성화·주기 변경·FF 재시작: 지정한 간격이 지난 뒤 첫 실행
- 자동 수집 해제: 예약 취소

기본값은 자동 수집 OFF, 간격 180분, 작품당 최대 10회차, 요청 간격 1.5초, EPUB ON, 작가의 말 OFF입니다. 설정과 이력을 유지하려면 FF 데이터 볼륨을 보존하세요. 이력 DB는 `db/munpia_gold_history.db`입니다.

## 확인 범위와 검증

문피아 공개 모바일 JavaScript에서 `purchased`로 구매완료를, `remainRentSec`로 대여 잔여 시간을 표시하는 것을 확인했습니다. 현재 공개 회차 목록 API에서도 `free`, `purchased`, `rented`, `remainRentSec` 필드를 확인했습니다.

**구매 상태와 모바일 웹 본문 제공 여부는 별개입니다. PC 정상 열람이 곧 이 플러그인의 다운로드 지원을 뜻하지 않습니다.** 구매 완료여도 서버가 `A002_21014` 또는 `A002_21015`(앱 전용 열람)를 반환하면 이 방식으로 저장할 수 없습니다. v0.1.2에서 이를 쿠키 오류와 구분해 안내합니다. 실제 계정 테스트에서 구매 상태 판별은 확인했지만 해당 구매 회차는 모바일 API의 앱 전용 안내 응답으로 본문을 받지 못했습니다. 사용자는 같은 회차가 PC에서 정상 열람됨을 확인했습니다. PC 뷰어는 별도의 암호화 콘텐츠 처리·Canvas 렌더링을 사용하며 현재 플러그인은 이 경로를 지원하지 않습니다. 유효 대여 본문 수신은 아직 확인하지 못했습니다. 처음에는 구매 회차 1개와 대여 회차 1개를 따로 시험하세요. 상태 표시나 본문 요청이 실패하면 쿠키 값 대신 작품 URL과 다운로드 이력의 오류 문구를 알려주세요.

```bash
python -m unittest discover -s tests -v
```

합성 데이터로 무료·구매·유효 대여 선별, 미구매/만료/불명확 상태 차단, 큐 대기·요청 대기 중 대여 만료, 목록 갱신 후 권한 취소, GET 전용 요청과 결제 API 차단, 쿠키 처리, TXT/EPUB·이미지, 설정 저장 시 수집 방지를 검사합니다. 테스트에 실제 소설 본문이나 계정 쿠키는 포함하지 않습니다.
